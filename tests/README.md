## Isolated Rust fixtures

Rust integration tests should import `src-tauri/tests/common/mod.rs` and use:

- `TestAppDir` for a unique application-data tree beneath the system temporary directory.
- `TestAppDir::open_migrated_database()` for SQLite initialized by the real migration runner.
- `TestDatabase` for note, notebook, tag, attachment, and reopen helpers.
- `lock_process_global_test_state()` only when a test changes production process-global state such as the security audit sink or backup/restore concurrency flags.

Each root uses the reserved `personal-notepad-test-` prefix and an exact safety marker. Cleanup refuses paths without both safeguards, removes only the owned root, and surfaces cleanup failures. Do not construct test storage from the normal application-data resolver.

Debug desktop tests may set `PERSONAL_NOTEPAD_TEST_DATA_DIR` to a root created by the canonical fixture. The Tauri application independently validates that it is a marked direct child of the system temporary directory. Release builds ignore this override.

### Continuous Integration Configuration

Continuous Integration is automated via GitHub Actions in [`.github/workflows/ci.yml`](file:///home/ritiksaini/Desktop/localhost/own/custom-notepad/.github/workflows/ci.yml).
- **Triggers**: Executed on every push and pull request targeting the `main` branch.
- **Job 1 (`frontend-quality`)**: Runs on `ubuntu-latest`, executes `npm ci` (respecting `package-lock.json`), `npm run typecheck`, `npm run lint`, `npm test`, and `npm run build`.
- **Job 2 (`rust-quality`)**: Runs on `ubuntu-latest`, installs WebKit/GTK system packages, caches Cargo dependencies, runs `cargo fmt --check`, `cargo check`, `cargo clippy`, database migration tests, regression tests, critical E2E tests, and full test suites.

### Environment Prerequisites & Headless CI Alternatives

- **Native Linux GUI Prerequisites**: Building the desktop application requires WebKit2GTK and GTK3 development headers:
  `sudo apt install -y libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev`
- **Headless Desktop Tests**: Interactive desktop GUI workflows requiring rendered displays can run locally or in virtual framebuffers (`xvfb-run npm run build:desktop`). Backend integration suites use `TestAppDir` without requiring an active X11/Wayland display server.



## Editor history and preview regression coverage

`npm test` includes `editor-history.test.mjs`, which exercises the production history/shortcut and Markdown parser implementations. `npm run test:editor:browser` builds and mounts the real editor in headless Chromium with strictly mocked Tauri calls, synthetic notes and a fresh temporary browser profile. It checks keyboard/toolbar history, preview transitions, Tab autosave, link/image insertion, read-only protection and whitespace rendering. It does not connect to the installed application or its notes. The runner prints the temporary artifact directory. Set `EDITOR_TEST_BROWSER` to select another Chromium-compatible executable.

See `docs/audits/editor-undo-spacing-2026-10-23.md` for the audit findings, implemented fixes and verification boundaries.
